## 范围与固定设置

题目包含 16 道结构化题、16 道文献题、9 道混合题和 12 道边界题，沿用单来源修订版题意。来源报告范围包含选定的 6,840 行、全部 21 个原始字段，以及三个保留近似定位和不确定性的文献区域。来源记录与公共数据发布成员资格分开，HCVR No、Failed 及作者的 putative 等限定均保留。

生成模型为本地 `mlx-community/Qwen3-4B-Instruct-2507-4bit`，版本 `50d427756c6b1b2fe0c0a10f67fbda1fc8e82c1b`。各生成条件共用提示词和题目，温度 0、seed 0、串行运行、自动重试 0。固定输入上限 24,576 tokens，输出上限 8,192 tokens，总上下文 32,768 tokens，操作超时 300 秒。模型工作进程禁止联网、工具调用和跨题记忆；检索访问隔离的只读实验库。

| 条件 | 回答路径 |
|---|---|
| S0 | 模型仅接收问题，不接收检索证据 |
| S1 | 完整固定材料直接输入；实际分词超限则记录，不截断 |
| S2 | PostgreSQL English FTS 检索后交给模型 |
| S3 | 原有关键词、BGE 向量与摘要向量检索，经 RRF 排序后交给模型 |
| S4 | 来源报告白名单查询，直接返回完整结构化结果，不生成 |
| S5 | 完整来源报告查询加文献锚点检索，再由模型回答 |
| S6 | 按已采用的逐题 Oracle 加载原始证据，再由模型回答 |

S4/S5 使用独立版本的 `source-reported-v1` 扩展。原公共发布门禁和历史系统定义保留，来源报告不会自动升级为已验证的公开 EVE 位点。实现入口见[来源报告版运行说明](rag_value_source_runtime.cn.md)及[正式执行脚本](../scripts/run_rag_value_source_experiment.py)。

## 结果解释的限制

**S2 本次没有提供检索证据。** 48 个通过共同范围检查的 S2 单元均保存了 FTS 执行事件，但候选键和传给模型的引用段落数均为 0，没有截断或省略。对应 48 组 S0/S2 的证据包及原始回答完全相同；另外 5 题在所有系统中均先被范围规则拒绝。

冻结实现把完整问题交给 PostgreSQL 的 `websearch_to_tsquery`，使用 `english` 配置和固定语料筛选，没有先抽取关键词。记录支持“该固定查询路径未返回候选”这一观察，但未保存数据库原始 tsquery、游标输出或查询计划，不能据此确定是词项、查询组合、词典还是语料筛选导致空结果。因此本次 S0/S2 比较不能衡量成功检索到关键词证据后的帮助，也不能推论关键词检索普遍无效。

**S1 和 S6 的预算限制必须单列。** S1 的 48 个适用单元均超限，实际输入为 4,167,263–4,167,345 tokens，完整材料保留、未生成。S6 有 16 个输入超限和 18 个模型超时；大集合超限的单元不能作为“模型在可用的充分证据下回答”的 Oracle 上限，不能据此将失败归因为模型理解能力。S6 已确认生成的 14 个单元也仍需后续科学评分。

本次在正式运行后没有更改提示词、删除证据或重跑不理想答案。来源图文冲突和旧分类名称继续分源保留，不通过运行结果反向修订 Gold。
