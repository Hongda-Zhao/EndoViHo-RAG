## 共同提示词：你只需要理解这些规则

- 用英文回答，只依据本次提供的证据；证据不足就明确说不知道。
- 数量、Assembly、序列编号、位点、坐标和 release 原样保留；不能补造。
- 文献事实要引用对应段落；不能将分类归属解释成现代感染、流行率、物种缺失或独立整合事件。
- 保留原始注释和分类版本；当前 53 题不要求自动判定 Transferred gene / Integrated virus，也不需要为此补新定义。
- 各组使用同一输出格式；技术 JSON 可以另外转成供人阅读的表格。

完整英文以 [现有 prompting.py](../src/eve_relation_rag/experiments/rag_value_ablation/prompting.py) 为准，不另写一套可执行提示词。本次只读生成的 policy SHA-256 为 `52c87dc8d69cfebfba1bce3dbd5f36f2af9876d18365c0c3937741b47976692f`。

解释结果时须注明：同一提示词禁止使用外部知识，S0 又没有输入证据，因此拒答是合法结果。这测量的是该证据约束政策下的表现，不能把 S0 的拒答直接解释为模型没有相应常识。

## PubMed 和 Google Scholar 怎么用

可以用于准备文献，不在正式答题时现场搜索。

- PubMed 有官方检索 API；其记录主要是题录和摘要，不等于全文。全文从 PMC 或出版方获取，逐篇核对许可；只使用免费且允许本实验使用的材料。[NCBI API](https://www.ncbi.nlm.nih.gov/home/develop/api/)、[PubMed 全文说明](https://pubmed.ncbi.nlm.nih.gov/help/#finding-the-full-text-article)。
- Google Scholar 可用于人工补充找文献。官方不提供批量访问，因此本方案不建立 Scholar 批量抓取器，也不购买第三方接口。[Google Scholar 说明](https://scholar.google.com/intl/us/scholar/help.html#export)。
- 准备完成后固定论文版本、文件校验和、文档与段落编号、切分规则及许可清单，形成独立的实验语料版本。检索条件使用同一语料；S0 不接收语料，S6 只接收其中经人工批准的 Oracle 证据。
- 新增论文不直接写入现有已发布 corpus，不覆盖现有 embeddings。准备阶段下载范围尚未批准；本轮仅查阅官方使用说明，没有下载论文。

## 文献最低数量与作者置信度：用户追加决定

用户明确将最低证据要求改为一篇文献，同时要求保留各篇文献对相关关联的判断和置信度。这里的“足够”是足够支持与原文强度一致的具体回答，不是只要出现关键词就算证实，也不替代人工 Gold／Oracle 核对。

所选固定语料中，所有与该关联相关的论文均需逐篇记录：对象、作者实际主张、原文中的确定／可能／推测等措辞、作者明确报告的数值与指标含义（如有）、原文段落位置。没有报告置信度就写“未报告”；没有检查原文就写“未检查”，二者不能混用。文章之间相互矛盾或同一篇文章含有多个判断时，分别保留，不生成一个综合置信度，也不自动升级成关系分类。

当前契约本来就允许一篇文献。旧 53 题中仅 `HOST-H-02`、`VIRUS-H-02`、`REL-H-02` 的题目要求至少两篇；其新措辞和逐来源记录规范见 [单篇证据与作者置信度规则](rag_value_source_evidence_policy.cn.md)。这项决定不减少 53 题，不改变分组，也不取消运行后两位独立专家的盲审要求。

## 结构化数据是什么

它是项目已有的事实表：哪个分类单元下的哪个物种／Assembly，包含哪些位点，各位点是什么病毒谱系、坐标在哪里、依据哪个来源。它不是 PubMed 的搜索结果，也不是模型生成的答案。

建议先用 [现有 mini 数据包](../data/releases/endoviho-mini-v1/README.md) 检查工程流程：3 个 Assembly、11 个位点、一个来源宿主科、一个生物学病毒谱系。其研究标签与 ICTV 更名后的标签不能算成两个独立谱系。该包已发布为文件，但尚未激活到数据库；本轮只读校验通过，没有导入或修改数据库。

它不能直接当作覆盖全部 53 题的完整数据。正式 DatasetRelease 和 CorpusRelease 尚未选定，不能自动用历史候选数据替换、删题或把缺失证据标成批准。后续先整理各题的数据覆盖和所需共享对象，再让用户核对具体内容；用户不需要手填 release 哈希。

## 当时正式运行还缺什么

1. 工程：补齐真实 S0–S6 隔离执行、只读数据库与 release 检查、必要的集合查询及条件性回答评分；已有合成测试不代表真实运行入口完成。
2. 数据：确认覆盖 53 题的固定数据、固定文献和 9 个共享对象；不足处明确列出。
3. 最少人工核对：共用事实和原文证据只核实一次，多题引用；再核对各题的答案范围，并单独允许将已核实证据用于 Oracle。已批准的题意和分组不重审。
4. 运行前：验证本地模型文件、tokenizer、依赖、内存额度和隔离条件，冻结精确运行 manifest。本文不签发运行许可，也不补写审核人或审核时间。

完整科学结论仍需运行后的独立专家盲审。该历史记录形成时，模型和预算已经确定，正式运行结果尚未生成；最终机器执行结果见本页开头的公开摘要。
