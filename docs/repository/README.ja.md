# EndoViHo-RAG

**EVE データと論文を先に調べ、根拠とともに回答するローカル研究ツールです。**

> 現在はエンジニアリング・プレビュー版です。公開済みの生物学知識ベースではなく、新たな
> 生物学的結論を自動的に導き出す用途には使用しないでください。

## 30秒でわかるこのプロジェクト

検索拡張生成（Retrieval-Augmented Generation; RAG）は、「資料持ち込み可の試験」に
例えられます。システムは AI の記憶だけで回答するのではなく、まずデータベースや論文から
資料を探し、見つかった根拠をもとに回答をまとめ、出典を残します。

```text
質問する → EVE データベースと論文を検索 → 関連する根拠を見つける → 回答をまとめる → 出典を添える
```

内在性ウイルス配列（endogenous viral element; EVE）は、宿主ゲノムに残されたウイルス
由来配列の記録です。EndoViHo-RAG は、研究者が各レコードの出所、論文中のどの箇所が
それを裏づけているか、そしてシステムがなぜ回答したのか、または回答しなかったのかを
追跡できるようにすることを目指しています。

このリポジトリが主に提供するものは次のとおりです。

- PostgreSQL に格納された、出典を追跡できる EVE の構造化レコード。
- 固定した論文コーパスに対するキーワード検索とセマンティック検索。
- FastAPI、コマンドライン、および Streamlit のウェブデモ。
- 出典付きの回答フローと、データや根拠が不十分な場合の明示的な回答拒否。
- オフラインかつバージョン固定で、再現可能なモデル比較実験。

これは自由対話型のチャットボットではありません。また、本システム単独では、感染、流行率、
独立した組込み事象、共進化、その他の新たな生物学的結論を立証できません。

## 最新の結果：どの文献検索構成が適しているか？

システムが正しい論文箇所を見つけやすくなるよう、BGE、MedCPT、Qwen3 を比較しました。
これらは異なる「電子図書館員」と考えることができます。「検索モデル」がすべての資料から
候補となる文章を探し、「再ランキングモデル」がその候補を並べ直します。

6つの構成はすべて、同じ資料、同じ質問、同じ検索ルールを使用し、モデルの組み合わせだけを
変更しました。

![6種類の文献検索構成における正解根拠のヒット数と待ち時間の比較](../assets/retrieval_ablation_overview.png)

*左図は、上位5件の結果に正しい根拠が含まれていたかを示します。右図は、1問あたりの
典型的な待ち時間を示します。右図は対数目盛のため、右に寄るほど大幅に遅いことを意味します。*

### 先に結論

1. **当面は現行の BGE 構成を維持します。** 13問中11問で正しい根拠を見つけ、典型的な
   待ち時間は約0.08秒でした。現時点では、品質と速度のバランスが最も良い構成です。
2. **MedCPT の検索と再ランキングの組み合わせが、最も多く正しい根拠を見つけました。**
   13問中12問で、現行構成より1問多く見つけましたが、典型的な待ち時間は約2.46秒で、
   約29倍遅くなりました。
3. **Qwen3 を検索だけに使用すると、正しい根拠が上位に並ぶ傾向がありました。** ただし、
   上位5件で正しい根拠を見つけた質問数は増えず、典型的な待ち時間は約0.99秒で、
   約12倍遅くなりました。
4. **現在の Qwen3 再ランキング構成は割に合いません。** 正しい根拠を見つけたのは10問
   のみで、典型的な待ち時間は約3分42秒でした。

| 構成 | 上位5件で正しい根拠を発見 | 根拠順位スコア | 典型的な待ち時間 | 平易な説明 |
|---|---:|---:|---:|---|
| A · 現行 BGE 構成 | **11 / 13** | 0.716 | **0.08秒** | 現時点で最もバランスが良い |
| B · 現行構成 + MedCPT 再ランキング | 11 / 13 | 0.541 | 2.75秒 | 遅くなり、順位も悪化 |
| C · MedCPT 検索 | 11 / 13 | 0.651 | **0.05秒** | 処理は最速だが、全体の順位はやや弱い |
| C+ · MedCPT 検索 + 再ランキング | **12 / 13** | 0.599 | 2.46秒 | 1問多く見つけるが、明らかに遅い |
| D · Qwen3 検索 | 11 / 13 | **0.742** | 0.99秒 | 順位は最も良いが、見つけた質問数は増えない |
| D+ · Qwen3 検索 + 再ランキング | 10 / 13 | 0.526 | 3分42秒 | 現時点では採用に値しない |

「根拠順位スコア」は MRR@10 です。値は0から1の範囲で、高いほど正しい根拠が上位に現れる
傾向があります。「典型的な待ち時間」はエンドツーエンド遅延の中央値で、モデルの初回
読み込み時間は含みません。読者は通常、上位数件が正しいか、どのくらい待つ必要があるかを
重視するため、「上位10件のどこかに正しい根拠があるか」だけでモデルを選ぶことはできません。

### 比較条件は公平だったか？

6つの構成はすべて、次の条件を固定しました。

- 同一の11本の文献。ファイルはバイト単位で完全に同一。
- 同一の1,464個のテキスト断片。特定のモデル向けに論文を分割し直していない。
- 同一の13問の実際の質問。
- 同一のキーワード検索、アンカー、RRF 統合ルール、および返却件数。
- 同一の Apple M2、16 GiB、CPU のみの環境。
- ローカルに保存され、バージョンが固定され、チェックサム検証済みのモデルファイル。
  実行時はネットワークに接続しない。

実験は本番系から分離した独立の sidecar で実施し、リリース済みコーパス、本番用埋め込み
ベクトル、データベースの次元数、本番環境のデフォルト値を上書きしていません。

> **重要な制限：これは初期的な結果であり、正式なモデル選定の結論ではありません。**
> 現在の13問は従来の暫定ゴールドデータ（legacy gold）です。専門家による承認を完了した
> 質問はまだ1問もなく（`approved = 0`）、質問カテゴリ、代替根拠、除外根拠の
> アノテーションも十分ではありません。現行構成を置き換えるかどうかは、専門家承認済みの
> 質問を30～50問まで増やしてから判断する必要があります。

完全な指標、モデルのバージョン、リソース使用量、再現手順については、
[技術レポート](../embedding_reranker_ablation.md)と
[機械可読な結果](../../benchmark/embedding_ablation/)を参照してください。

## 現時点でどこまで動作するか？

コード、データベースマイグレーション、API、CLI、ウェブデモ、Docker Compose、自動テストは
すべて実行できます。ただし、このリポジトリは実際の構造化データ、論文全文、モデル重みを
配布せず、モデルを自動的にダウンロードすることもありません。新規インストールでは
データベースは空です。必要なデータがないリクエストでは、サンプルデータを実データに
見せかけるのではなく、回答できない理由を明示します。

本番設定では、現在テキスト生成モデルが無効になっています。つまり、このリポジトリには
監査可能なエンジニアリング基盤と実際の検索実験がありますが、すぐに使える完全な
科学データ製品ではありません。

## クイックスタート

Git と Docker Compose が必要です。初回ビルドでは、バージョン固定されたコンテナイメージと
依存関係を取得するため、インターネット接続が必要です。

```sh
git clone https://github.com/Hongda-Zhao/EndoViHo-RAG.git
cd EndoViHo-RAG
cp .env.example .env
docker compose up --detach --build --wait
```

起動後、次のページを開けます。

- ウェブデモ：<http://127.0.0.1:8501>
- API ドキュメント：<http://127.0.0.1:8000/docs>
- ヘルスチェック：<http://127.0.0.1:8000/health>

サービスが起動したか確認します。

```sh
curl -sS -w '\nHTTP %{http_code}\n' http://127.0.0.1:8000/health
```

期待される出力：

```text
{"status":"ok","service":"EVE Relation RAG","version":"V0"}
HTTP 200
```

これはプログラムが起動したことだけを示し、実際のデータ、論文、モデルが読み込まれたことを
意味しません。ローカルデータベースを残したままサービスを停止するには、次を実行します。

```sh
docker compose down
```

## 開発と検証

このプロジェクトは Python 3.12、uv、PostgreSQL 16、pgvector を使用します。標準の
検証コマンドは次のとおりです。

```sh
. scripts/local-dev-env.sh
uv sync --locked --dev --extra demo
docker compose up -d db
uv run alembic upgrade head
uv run pytest
uv run ruff check .
uv run mypy src app
uv lock --check
uv run alembic check
```

ローカル embedding 実行環境は別途インストールする必要があります。

```sh
uv sync --locked --dev --extra demo --extra local-embeddings
```

モデルは、ローカルにあり、リビジョンが固定され、SHA-256 マニフェストで検証済みの
ディレクトリから明示的に読み込む必要があります。システムは、モデル、データ、論文、
`release`、`binding` を自動的に検出またはダウンロードしません。
